## Design Specificity Verdict
Authored for this business, not a reskinned template: pattern-rack nav structurally solves the 10-category wayfinding problem, chalk snap-lines are a literal pattern-drafting callback, copy is agency-specific (SA licence codes, POPIA, Gauteng default). Grayscale executed with discipline, verified WCAG AAA (8.15-9.74:1) everywhere sampled. The forms are the one place the bespoke world-building drops out — a generic two-column enterprise-SaaS grid.

Detector ran DEGRADED (regex fallback, parser deps unavailable — undercount, not clean bill of health). One finding: em-dash-overuse (17, advisory only). No console errors, no broken links, all 11 images + assets 200 OK.

## Priority Issues

[P0] Sensitive PII collected before consent shown — Candidate form places ID Number/DOB/Next of Kin near top, POPIA consent at the very bottom of 23 fields. Fix: move consent above sensitive fields.

[P0] Form "success" is unconditional and can lie — main.js posts with mode:'no-cors', app can never read real HTTP response; user always sees "Received" regardless of backend outcome. Fix: CORS-enabled confirmation path or confirmation email.

[P1] Form tab switching breaks aria-selected — verified in DOM: visual state toggles correctly but aria-selected never updates; screen readers announce wrong tab. Fix: update aria-selected in main.js click handler.

[P1] Forms contradict the page's own minimalism — 19/23 fields in one flat grid, no grouping, no conditional reveal; 5/8 cognitive-load checklist items fail, concentrated entirely here. Fix: chunk into labeled sub-groups.

[P1] Required-field markers have no visual salience — asterisk uses same color as headings; inconsistent (optional) labeling. Fix: apply (optional) consistently or separate required/optional clusters.

## Persona Red Flags
First-time visitor: Role Needed doesn't pre-select from category-page intent; confirmation gives no timeframe/channel despite capturing Preferred Contact Method.
Mobile candidate: form ~2,254px tall at 375px, zero progress indication; native DOB picker; no inputmode=numeric on ID Number.
Stress-tester: no pattern validation on Mobile field; network-kill fallback message works well; double-submit correctly guarded.

## Minor Observations
Hero eyebrow orphans "JOHANNESBURG" at 375px. Placeholder text 2.81:1 contrast (below AA). No format validation on Mobile/ID/DOB. Hairline borders ~1.3:1 (likely deliberate). One inline style on Personal Assistants heading.

## Questions to Consider
1. Why are the forms the least crafted part of a site built on a "precise measurements" metaphor?
2. Is a fire-and-forget no-cors POST an acceptable trust foundation for collecting SA ID numbers?
3. Would light grouping of the 10 categories better match a first-timer's mental model than a flat list?
